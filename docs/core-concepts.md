## Evaluation Philosophy

### Why Multiple Judges?

Single-model evaluation is prone to:
- **Bias**: Each model has inherent preferences and blind spots
- **Inconsistency**: Repeated evaluations may yield different scores
- **Lack of confidence metrics**: No way to measure certainty

Multi-model consensus addresses these issues by:
- Averaging out individual biases
- Providing confidence scores based on agreement
- Creating transparent audit trails

### The "Wisdom of the Crowd" Effect

Just as human juries leverage diverse perspectives, LLM Jury aggregates multiple model opinions to reach more reliable verdicts.

## The Jury Pattern

The evaluation process follows a structured pattern:

```
Input → Judges → Individual Scores → Aggregation → Final Result
```

### 1. Input Preparation
- **Context**: Source material, retrieved documents, or reference text
- **Output**: The LLM-generated content to evaluate
- **Metric**: The evaluation criteria to apply

### 2. Parallel Judgment
Each judge independently evaluates the output:
- Receives the same prompt (generated by the Metric)
- Returns a score and reasoning
- No inter-judge communication (prevents groupthink)

### 3. Score Aggregation
An AggregationStrategy combines individual scores:
- **MajorityVoting**: Most frequent score wins
- **Consensus**: Requires threshold agreement
- **Weighted**: Some judges have more influence

### 4. Manifest Generation
Complete audit trail including:
- All individual scores and reasoning
- Extracted text features
- Aggregation metadata
- Timestamp and configuration

## Key Components

### Judges

**Purpose**: Evaluate content based on provided prompts

**Types**:
- `LLMJudge`: Wraps any LangChain model
- `CustomJudge`: User-defined evaluation functions
- Future: Rule-based, hybrid judges

**Responsibilities**:
- Parse evaluation prompts
- Query underlying model/function
- Extract score and reasoning from response
- Return structured `JudgeScore` object

**Example**:
```python
from llm_jury.judges.llm_judge import LLMJudge
from langchain_openai import ChatOpenAI

judge = LLMJudge(
    model=ChatOpenAI(model="gpt-4"),
    name="gpt-4-judge"
)

score = judge.evaluate_score(
    prompt="Rate this text for clarity (1-5)",
    context={"output_text": "The sky is blue."}
)
# Returns: JudgeScore(score=4.0, reasoning="Clear and concise", judge_id="gpt-4-judge")
```

### Metrics

**Purpose**: Define what and how to evaluate

**Responsibilities**:
- Generate evaluation prompts for judges
- Define scoring scales (e.g., 1-5, 0-1, binary)
- Normalize scores to unified ranges
- Provide evaluation criteria

**Built-in Metrics**:

1. **GroundednessMetric**
   - Verifies claims are supported by source text
   - Scale: 1-5 (fully grounded to completely unsupported)
   - Use case: RAG systems, fact-checking

2. **HallucinationMetric**
   - Detects fabricated or illogical content
   - Scale: 0-1 (no hallucination to definite hallucination)
   - Use case: General content validation

**Custom Metrics**:
```python
from llm_jury.metrics.base import Metric

class ProfessionalToneMetric(Metric):
    def __init__(self):
        super().__init__(
            name="ProfessionalTone",
            description="Evaluates business-appropriate language",
            scale_min=1.0,
            scale_max=5.0
        )
    
    def get_prompt(self, context=None):
        output = context.get("output_text", "")
        return f"""
        Evaluate the following text for professional tone:
        {output}
        
        Score 1-5 where:
        5 = Exemplary professional tone
        1 = Completely unprofessional
        
        Score: <number>
        Reasoning: <explanation>
        """
```

### Aggregation Strategies

**Purpose**: Combine multiple judge scores into a single verdict

**Available Strategies**:

#### MajorityVoting
Selects the most common score (plurality).

```python
from llm_jury.strategies.consensus import MajorityVoting

strategy = MajorityVoting()
result = strategy.aggregate(judge_scores)
# Returns: AggregationResult(score=4.0, confidence=0.67, metadata={...})
```

**Use when**: You want democratic decision-making with clear winners.

#### ConsensusStrategy
Requires a minimum agreement threshold.

```python
from llm_jury.strategies.consensus import ConsensusStrategy

strategy = ConsensusStrategy(threshold=0.6)  # 60% agreement required
result = strategy.aggregate(judge_scores)
```

**Use when**: High confidence is critical (e.g., compliance checks).

#### WeightedSum
Assigns different weights to judges.

```python
from llm_jury.strategies.weighted import WeightedSum

strategy = WeightedSum(weights={
    "gpt-4": 1.0,
    "gpt-3.5": 0.5,
    "llama-2": 0.3
})
result = strategy.aggregate(judge_scores)
```

**Use when**: Some models are more reliable for your specific domain.

### Feature Extraction

**Purpose**: Analyze text to provide quantitative features

**Extracted Features**:

1. **Text Metrics**
   - Character count
   - Word count
   - Sentence count
   - Paragraph count
   - Compression ratio (information density)

2. **Complexity Metrics**
   - Flesch Reading Ease score
   - Lexical diversity (type-token ratio)
   - Average sentence length
   - Difficult word count

3. **Special Features**
   - Modality verb usage
   - Shannon entropy
   - Pattern detection

**Usage**:
```python
from llm_jury.features.extractor import FeatureExtractor

extractor = FeatureExtractor()
features = extractor.extract_text_metrics(text)
# Returns: {"word_count": 150, "flesch_reading_ease": 65.2, ...}
```

Features are automatically included in the evaluation manifest for analysis and debugging.

---

### Manifests

**Purpose**: Complete audit trail of evaluation process

**Contents**:
- Individual judge scores and reasoning
- Extracted text features
- Aggregation metadata (strategy, vote distribution)
- Timestamp and configuration

**Structure**:
```python
@dataclass
class JuryManifest:
    individual_scores: List[JudgeScore]
    features: Dict[str, Any]
    metadata: Dict[str, Any]
    timestamp: datetime
```

**Why Manifests Matter**:
- **Debugging**: Understand why a score was assigned
- **Analysis**: Track judge agreement patterns over time
- **Compliance**: Provide audit trails for regulated industries
- **Improvement**: Identify when to add/remove judges or adjust weights

## Evaluation Workflow

Here's the complete flow when you call `jury.evaluate()`:

```
1. Input Validation
   ├── Validate context structure
   └── Check output is not empty

2. Feature Extraction
   ├── Extract text metrics
   ├── Calculate complexity scores
   └── Compute special features

3. Prompt Generation
   ├── Metric generates evaluation prompt
   └── Context injected into prompt template

4. Parallel Judge Execution
   ├── Each judge evaluates independently
   ├── Scores extracted via regex/JSON parsing
   └── Failures logged but don't crash evaluation

5. Score Normalization (if needed)
   ├── Check if strategy requires [0,1] range
   └── Apply metric.normalize() if needed

6. Aggregation
   ├── Strategy combines all scores
   ├── Calculates confidence metric
   └── Packages metadata

7. Manifest Creation
   ├── Collect all individual scores
   ├── Include extracted features
   └── Add aggregation metadata

8. Result Return
   └── EvaluationResult with score, validity, confidence, manifest
```

### Execution Details

**Parallelization**: Judges run concurrently using `ThreadPoolExecutor` to minimize latency when using API-based models.

**Error Handling**: If a judge fails (API error, timeout, parsing failure), the evaluation continues with remaining judges. Failed judges are logged but don't crash the entire jury.

**Score Normalization**: The system intelligently normalizes scores based on the aggregation strategy:
- `WeightedSum` requires normalized [0,1] scores
- `MajorityVoting` works with raw discrete scores
- Normalization uses the metric's defined scale

## Design Principles

### 1. Modularity
Each component has a single responsibility and can be swapped independently.

### 2. Extensibility
Abstract base classes make it easy to create custom:
- Judges (wrap any model or function)
- Metrics (domain-specific criteria)
- Strategies (novel aggregation methods)

### 3. Transparency
Every evaluation produces a complete manifest showing:
- What each judge said
- Why they said it
- How scores were combined

### 4. Pragmatism
Sensible defaults for quick starts:
- Default to MajorityVoting if no strategy specified
- Automatic feature extraction
- Graceful degradation on errors

### 5. LangChain Integration
Built on LangChain for:
- Broad model support (OpenAI, Anthropic, Google, open-source)
- Standardized interfaces
- Easy composition with existing pipelines
